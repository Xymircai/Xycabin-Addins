**三项目接手入口**

# 一. 开发接手入口

## 1. 入口与阅读顺序

本文件是唯一入口：先在此完成分流，再进入对应文档。文档清单、项目与版本表只在 [B1 第一章](B1-Project-Files.md#一-agent及开发者接手概览) 维护，本节不重复。

| 任务     | 阅读顺序                                            | 目的         |
| ------ | ----------------------------------------------- | ---------- |
| 首次接手   | 本文件 → B1 第一章                                    | 建立项目与文档地图  |
| 安装/使用  | [A-UserGuide](A-UserGuide.md) 对应产品章 → B1 对应版本摘要 | 用户步骤与当前版本  |
| 查找功能代码 | [B4-Code Index](<B4-Code Index.md>) 对应产品与选项卡 | 按界面名称定位目录、回调与依赖 |
| 改代码/排障 | B1 对应项目档案 → B2 对应专属经验                           | 定位实现与边界    |
| 发布/验收  | [B3（Spec Coding）](<B3-Spec Coding.md>) 第一章 → B1 对应项目档案的「当前状态与交付」                    | 交付、恢复与验收边界 |

仓库根 `AGENTS.md` 只指向本文件，不维护任何规则。

## 2. 三个输出的关系

| Excel-Iterate | C-01-ExcelIterate    | WPS 表格加载项；`AA-Program` 放配置器、启动器和安装包，`AB-Graphic` 放界面截图与功能区资源 |

## 3. 共享与同步

公共实现只在同级 `C-00-Shared` 维护。C-01/C-02 的 project.json 用 `@shared/` 直接编译引用；产品脚本仅保留显式传入产品根目录的薄入口，不增加运行时公共 DLL。运行仓库根 `verify_shared.py` 校验公共实现唯一、引用有效及必要二进制依赖一致；公共改动同时进入两产品缓存指纹。源码携带需包含 C-00、相应产品、C-03 与 C-04；三个输出的文档仍只在 C-04-Devlog 维护。

## 4. 交付边界

沿用原版本、固定证书/私钥和稳定 ID。先固定非审计正文，再重建/签名/打包/验证，最后回填「本轮交付证据」；后台、历史及真实验收分开记录。构建不安装、不关闭 WPS。文档改动不触发冗余清理，实际清理指令才按正文执行。
